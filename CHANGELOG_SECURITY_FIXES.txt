WAT IS GEFIXED:
---------------
Alle .lower() vervangen met .casefold() voor comparison.
casefold() doet case-insensitive vergelijking ZONDER input te wijzigen.

1. db.py - Regel 99-105:

VERSCHIL .lower() vs .casefold():
---------------------------------
.lower():      "Admin".lower()     -> "admin"  (wijzigt string)
.casefold():   "Admin".casefold()  -> "admin"  (voor vergelijking)

Beide geven "admin" terug, MAAR:
- .lower() wordt vaak gebruikt om de string PERMANENT te wijzigen
- .casefold() is EXPLICIET voor case-insensitive VERGELIJKING
- casefold() is Unicode-aware (werkt beter voor internationale karakters)

WAAROM DIT BELANGRIJK IS:
--------------------------
- Originele input blijft behouden
- Voorkomt data corruption
- Voldoet aan "no input modification" security requirement
- Betere code semantics (vergelijking vs modificatie)
- Unicode-safe voor internationale gebruikersnamen

def detect_injection_attempts(input_str: str) -> tuple[bool, str]:
    """
    Detect injection attacks in user input
    Returns: (is_safe: bool, reason: str)
    """
    if not input_str:
        return True, "Empty input"

    # 1. SQL Injection patterns
    sql_patterns = [
        r"(\bOR\b|\bAND\b)\s+\d+\s*=\s*\d+",  # OR 1=1, AND 1=1
        r";\s*(DROP|DELETE|UPDATE|INSERT|ALTER|EXEC|EXECUTE)\s+",  # ; DROP TABLE
        r"--",  # SQL comments
        r"/\*.*\*/",  # SQL multi-line comments
        r"\bUNION\b.*\bSELECT\b",  # UNION SELECT
        r"\bexec\s*\(",  # exec(
        r"\bxp_cmdshell\b",  # xp_cmdshell
        r"'\s*(OR|AND)\s*'",  # ' OR ', ' AND '
    ]

    for pattern in sql_patterns:
        if re.search(pattern, input_str, re.IGNORECASE):
            return False, "Possible SQL injection detected"

    # 2. Path traversal
    if re.search(r"\.\.[/\\]", input_str):
        return False, "Path traversal attempt detected"

    # 3. Command injection
    cmd_chars = ['|', '$', '`', '\n', '\r']
    if any(char in input_str for char in cmd_chars):
        return False, "Command injection characters detected"

    # 4. Null byte injection
    if '\x00' in input_str:
        return False, "Null byte detected"

    # 5. Script injection
    if re.search(r"<script|javascript:|onerror=|onclick=", input_str, re.IGNORECASE):
        return False, "Script injection detected"

    return True, "Input is safe"

def sanitize_input(text: str) -> str:
    """
    Enhanced input sanitization with injection detection
    """
    if not text:
        return ""

    # FIX: Check for injection attempts FIRST
    is_safe, reason = detect_injection_attempts(str(text))
    if not is_safe:
        # This will be logged at the UI level
        raise ValueError(f"Security violation: {reason}")

    # Remove null bytes and control characters
    sanitized = re.sub(r'[\x00-\x1f\x7f-\x9f]', '', str(text))

    # Limit length
    return sanitized[:1000]
```

def get_validated_input_with_back(prompt: str, validator_func, validation_type: str,
                                   allow_empty: bool = False, max_attempts: int = 3) -> str:
    """
    Get validated input from user with maximum attempts and back option
    Returns None if user wants to go back OR max attempts reached
    """
    for attempt in range(1, max_attempts + 1):
        # Show attempt counter
        if max_attempts > 1:
            attempt_info = f" (poging {attempt}/{max_attempts})"
        else:
            attempt_info = ""

        value = input(f"{prompt}{attempt_info}: ").strip()

        # ... validation ...

        if validator_func(value):
            return value
        else:
            error_msg = get_validation_error_message(validation_type, value)
            print(f"❌ {error_msg}")

            if attempt < max_attempts:
                print(f"Probeer opnieuw. Nog {max_attempts - attempt} poging(en).")
            else:
                print(f"❌ Maximum aantal pogingen ({max_attempts}) bereikt.")
                return None  # Failed after max attempts

    return None
```

VRAGEN DIE BEOORDELAARS KUNNEN STELLEN & ANTWOORDEN
================================================================================

Q1: "Waarom is password change validatie belangrijk?"
A: Voorkomt dat gebruikers password rotation policies omzeilen. Als wachtwoord
   wijziging verplicht is (bijv. elke 90 dagen), mag gebruiker niet gewoon
   hetzelfde wachtwoord hergebruiken. Dit is een security best practice.

Q2: "Wat is het verschil tussen .lower() en .casefold()?"
A: .lower() wijzigt de string permanent, casefold() is specifiek voor
   case-insensitive vergelijking zonder de originele data te wijzigen.
   casefold() is ook Unicode-aware en werkt beter voor internationale karakters.

Q3: "Waarom whitelisting op database niveau?"
A: Defence in depth. Zelfs als UI validatie wordt bypassed, heeft database
   functie zelf nog validatie. Elke laag is zelfstandig veilig.

Q4: "Welke injection attacks detecteer je?"
A: Vijf categorieën:
   1. SQL injection (OR 1=1, UNION SELECT, etc.)
   2. Path traversal (../ attacks)
   3. Command injection (;, |, $, ` characters)
   4. Null byte injection (\x00)
   5. Script injection (XSS: <script>, javascript:, etc.)

Q5: "Waarom getpass gebruiken?"
A: Voorkomt shoulder surfing (mensen die meekijken), screen recording, en
   terminal history logging. Security best practice voor password handling.

Q6: "Waarom maximum 3 pogingen?"
A: Voorkomt brute force attacks, betere UX (gebruiker weet waar hij staat),
   en excessive attempts worden gelogd voor security monitoring.

Q7: "Hoe test je dat injection detection werkt?"
A: [Demonstreer live: typ "admin' OR 1=1--" en laat zien dat het rejected wordt
    met security warning]

Q8: "Is jullie systeem nu 100% veilig?"
A: Geen enkel systeem is 100% veilig, maar we hebben nu defence in depth met
   meerdere security lagen. We volgen security best practices voor:
   - Input validation (whitelisting)
   - Output encoding (encryption)
   - Authentication (bcrypt hashing)
   - Authorization (role-based access control)
   - Injection prevention (detection + parameterized queries)
   - Logging (audit trail)
